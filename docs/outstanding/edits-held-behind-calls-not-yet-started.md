| **While a call that may change the file system runs, and an answer may be a stop, a later call with side effects waits for every earlier call that has not started** ([architecture/03-agent-loop.md](../architecture/03-agent-loop.md), "A call is decided again"). The re-decide step of step 12 added the rule so that a turn still stops at a call in the model's order when that call's second decision is a stop. Where commands are confined (Linux by default) an answer may always be a stop, so the rule holds in the ordinary flow too: with `edit a`, `edit a`, `edit b` in one response, the edit of `b` no longer runs beside the first edit of `a`, and each edit's end has every call still waiting planned and decided again. Found by the full review of the step. **Why it was kept:** `write` and `edit` follow no link and make only regular files and directories, but a file they make can change what a later command's pattern matches (`rm *.lock` under a rule that holds `*.lock` back), and a directory they make can change how a later `cd` is followed, so leaving them out of the count could leave a second decision unmade. Slower, and never wrong. **What would settle it:** a measurement of what it costs a response of many edits on the desktop and on a runner, against the rows of [performance-budgets.md](../performance-budgets.md); and, if it matters, a narrower rule: hold only behind an earlier call whose second decision could differ, which needs the engine to say what of the file system a decision read. | The owner, with a measurement; step 32 (performance) unless sooner | Before the first release |
