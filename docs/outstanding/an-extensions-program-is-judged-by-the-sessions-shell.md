| **An extension's program is judged as a line of the session's shell.** `cineris.exec` runs a program directly, with no shell, but the engine reads its line in the session's shell's syntax, where the first word may be that shell's own command or alias: in PowerShell `write` is `Write-Output` and `cat` is `Get-Content`, read-only, while the program that runs is `write.exe` or an MSYS `cat`; and a quoted `-x` is text to PowerShell's table, an option to the program. Found by the early review of step 28's process starts. **The same reading keeps a rule from allowing some arguments on Windows:** an argument holding `%`, `& | < > ^` or `"`, one ending in `\`, or an empty one, makes the engine's reading of PowerShell stop modelling the line (`reaches_a_program_whole` in `cineris-policy`'s `powershell`), so that no rule and no safe list applies and the call is asked: refused in a hook and where nobody can be asked, asked each time for a command; `cineris.exec` gives a `.exe` the C runtime's quoting and refuses those characters to a `.cmd` or a `.bat`, so the caution does not apply to what runs. Found by step 28's `release` example (`git log --format=%h %s` refused with `--allow 'exec:git log *'`), which reads the log with `--oneline` for it. **Since step 28** an exec host call whose line was judged in PowerShell or `cmd`, and which the engine allows as read-only, is asked about instead (`HostQuestion::read_only_asks`; in a POSIX shell the judged name is the program, and nothing changes). **What would close it:** an `Exec` effect that says its line names an external program, which the engine judges by the rows of real programs only (`gh`, `git`, `whoami`) and whose arguments it reads exactly, as the list `cineris.exec` was given (or in POSIX quoting of it), never in the session shell's syntax; then the guard can go.
