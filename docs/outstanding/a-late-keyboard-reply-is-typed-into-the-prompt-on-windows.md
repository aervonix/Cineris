A system test of the interactive application timed out once on a hosted Windows runner, on `main`'s tree, because the terminal's late answer to the start-up query of the keyboard protocol was read as typed text and put in the prompt before the key the test sent.

- Area: cineris-term
- Owner: the maintainers, a small-fix session
- Flaky: `cineris-cli::system tui::sys_a_turn_with_tools_runs_in_the_interface_and_the_terminal_is_put_back`

| Item | Who | When |
|---|---|---|
| **What was seen.** In `try` run 45682764323 (step 28's script hooks, the Windows A/B, a hosted runner at 5 ms a process start), `tui::sys_a_turn_with_tools_runs_in_the_interface_and_the_terminal_is_put_back` failed once, on the **base side** (`main`, `d663b2ec`), in round 1 of 5; the pull request's side passed all five. It panicked at `crates/cineris-testkit/src/pty.rs`, line 259, the pty kit's wait running out: "waited 30s for the key's echo, and it did not happen" (`crates/cineris-cli/tests/system/tui.rs`, `type_timed`, which sends a key and waits for the prompt to show what was typed so far). The screen then held, in the prompt, `[?0uw`: the key sent (`w`) after the text `[?0u`. **Why, as far as is known:** as it enters the terminal, the application sends its queries (`cineris_term::Capabilities::QUERIES`), among them the enhanced keyboard protocol's flags (`ESC [ ? u`), to which a terminal that knows it answers `ESC [ ? 0 u`. Through the pseudo-console that answer came late, after the application had stopped waiting for its queries' answers, and the input reader took it as keys: an escape, then `[?0u` as text. The echo the test waits for is the whole word typed so far, so it never matched. **What it costs:** a test of `main`'s that fails at random on Windows, and, outside the tests, a user whose terminal answers late could find the same text in an empty prompt as the application starts. **What would close it:** the input reader recognising a late answer to the queries it sent (`ESC [ ? … u`, and the others of `QUERIES`) and dropping it rather than typing it, whenever it comes; then a test that delivers the answer after the start-up wait. [docs/conpty.md](../conpty.md) has what else ConPTY is known to do. | The maintainers, a small-fix session | Before the first release |
