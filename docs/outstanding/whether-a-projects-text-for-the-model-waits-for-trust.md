| **What happens today.** A project's instruction files (`AGENTS.md`, `CLAUDE.md`) load without project trust, and reach section 4 of the system prompt whole ([07-sessions-and-context.md](../architecture/07-sessions-and-context.md), "Project instruction files"); its skills (`.cineris/skills/`, and `.agents/skills/` and `.claude/skills/` under `compat.skills`) need no trust either, for the same reason, and each one's name, description and path reach section 6, a name cut to 64 bytes and a description to 300, on one line, with control and format characters taken out ([12-extensions.md](../architecture/12-extensions.md), "Tier 2: skills"; [06-permissions-and-sandbox.md](../architecture/06-permissions-and-sandbox.md), "Project trust"). They are text for the model: they cannot grant a permission or run anything. Step 28 raised the question while building section 6, and kept the documented rule: skills alone waiting for trust, while instruction files reach the model whole, would narrow the small channel and leave the wide one. **The case for waiting:** a fresh clone's text reaches the model before the user has been asked anything about the project; and section 6 is a standing invitation, telling the model to go and read a file whenever a task of its kind comes up, where an instruction file is read once. **The case against:** a fresh clone's own instructions and skills would be missing until the project is trusted, so the agent would work in it without the way the project asks to be worked in; and people who clone a repository expect its instructions to be read at once, as they are today, before any question. **The question:** should a project's instruction files and skills, together, wait for trust, or for a question of their own, or stay as they are? It is a product decision, for the owner. | The owner | Before the first release |
