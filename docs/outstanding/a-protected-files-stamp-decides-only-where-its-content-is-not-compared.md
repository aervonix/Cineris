The look at the protected paths compares a file's stamp only where neither its content nor its hash is known on both sides: a change of a protected file's owner alone, and a file replaced by another of the same bytes, are not counted as changes, and whether they should be is not decided.

Two questions are left for a decision: **(1) ownership:** the stamp holds no owner or group, so a change of a protected file's owner or group alone is seen by no arm (a confined command runs as the user, so it can give a file only to a group the user is in); **(2) a file replaced by another of the same bytes** (a new inode, such as a hard link to a file elsewhere, which a later write there would change): the content or the hash decides, so it is no change, and the inode is not consulted.
