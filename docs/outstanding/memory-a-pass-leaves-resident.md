| **Memory a pass of the repository index leaves resident.** The index holds nothing between uses ([performance-budgets.md](../performance-budgets.md), "Memory"), but the allocator keeps what a pass freed: on 20,000 files of real Rust, measured since the fixes of the independent review of step 18, the process went from 8.7 MB to 22.8 MB resident after its cold pass on the desktop (Linux, glibc) and from 7.5 MB to 11.4 MB on a hosted Windows runner; its peak was 32.5 to 48.5 MB on the desktop and 38.0 MB on Windows. Before those fixes the peak was 223 MB and 35.8 MB stayed. The idle budget for the TUI with a new session is 25 MB, and a session's first pass lands while it is idle. Repeated passes and maps grow it by nothing (`memory::passes_and_maps_leave_nothing_behind`). **Recommendation:** in step 33's memory pass, measure the idle TUI with a session whose index has made its first pass; if it is over the budget, give the allocator's free memory back after a pass (`malloc_trim` on glibc, which needs `unsafe` and `libc` in `cortex-index`, or an allocator that returns it), and measure the peak against the budget for a session's working set. | Step 33 (memory) | Before the first release |
