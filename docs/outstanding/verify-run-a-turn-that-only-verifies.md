In return the checks get everything a turn gives: the session is busy (nothing of the model's runs beside a check), an interrupt reaches them, a check that changes a protected path stops the turn, what a check changed is that turn's checkpoint for undo, and `turn.completed` carries the verdict. The other way, the core calling the verifier outside any turn, loses each of those, and the first two are not sound: a prompt could start a turn beside a running check, whose look at protected paths would then read the other's writes as a change from outside, and a check that changes a protected path would have no turn to stop.
