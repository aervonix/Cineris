| **The looks around a shell command follow the level when each is taken, not the command's start.** The look at the protected paths (`RecordingShell`), the look before at what the command changes (`ChangeDetector::before`), the start itself (`SessionSandbox::launch`) and the look after (`ChangeDetector::after`) each read whether commands are confined at their own moment. When the level is `unrestricted` at the looks before, is lowered before the start, so that the command runs confined, and is raised to `unrestricted` again before the look after, the protected paths are not looked at, and the look after runs the harness's git as it is: a filter the confined command planted in the repository's configuration runs with the user's full rights. Step 26's guard (`before.confined && !confines()`, which leaves the list incomplete rather than run git as it is) covers a level raised during a command, not this order. The project's checks run through the same shell and share the gap. It needs the user to change the level twice while one command runs, the first change between the looks before and the start; nothing a command does can change the level. Found while the fixes to step 28's process starts looked for the same mechanism as theirs (the look after an extension's program ran git at the session's level while the program was confined by its own launcher, fixed there by `FollowingTheProgram`). What was checked and holds: at `unrestricted` a command runs as it is and so does the git after it, the same rights; a level raised during a command is caught by the guard; the checkpoints' `git cat-file blob` after a program runs no program a repository's configuration names. **Recommendation:** decide a command's confinement once, when the look before it is taken, and have the start, the looks at the protected paths and the harness's git after it all follow that one decision: the launcher taken then rather than read again at the start, and the detector's git a confinement fixed to it, as the look after an extension's program is since step 28's fixes. | Step 32 (hardening pass) | Before the first release |
