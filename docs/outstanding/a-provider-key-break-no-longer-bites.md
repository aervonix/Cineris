No test can fail when one path alone is lost while both exist: each covers the other when a session starts. **Recommendation:** mark the old break `expect: survives`, naming `ShellLive` as what still removes the variables, or delete it; add a break at the source, `crates/cineris-core/src/provider.rs`, `in: key_variables`, `find: variables.push(variable);` with an empty `replace` (that `find` is there once), caught by the system test; and decide whether `assemble.rs`'s seeding of `env_remove` from `provider::key_variables` should go.
