The protected-path watch and the base state's git parsing handle mixed Windows path forms without `same_location`.

- Area: cortex-sandbox
- Owner: step 32, or the step that brings the sandbox to Windows

| Item | Who | When |
|---|---|---|
| **Two places compare paths of two forms on Windows that the comparison by place (`cortex_base::same_location`) does not reach.** (1) The protected-path watch keys its records by path (`crates/cortex-sandbox/src/protect.rs`): the workspace's own form is extended-length (`\\?\C:\…`, from `to_fs_path`) and a protected path from the lease is plain, so one file could be recorded twice. It is latent while the sandbox enforces on Linux only. (2) The base state asks git for the top of the repository and parses what it prints (`crates/cortex-session/src/base.rs`): git runs in the extended-length form there, and if it printed that form back the parse would refuse it and the workspace would be taken as the repository's top. (3) The same watch joins git's `commondir`, written with forward slashes (`../..`), onto the workspace's extended-length form, where Windows reads `/` and `..` literally, so the common directory's configuration and hooks are looked up at a path that is not there (found by the second review). Neither is shown to happen; none has a test on Windows. Found by the fourth tooling step's search for comparisons of the two forms. **Recommendation:** key and walk the watch by the plain form (`AbsPath::to_native_string`), and read git's answers through `AbsPath::from_os`, which takes the prefix off; add a Windows test of each when the sandbox reaches Windows. | Step 32 (hardening pass), or the step that brings the sandbox to Windows | Before the sandbox enforces on Windows |
