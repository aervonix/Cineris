| **The editor's cost on very large text is not measured against the key budget.** Every key lays the whole prompt out again (grapheme segmentation of all of it) and finds a chip's label by counting the chip marks before it, so after `Ctrl+X` expands a paste of several megabytes into the prompt each key costs time in proportion to it. And `Backspace` or `Left` inside an `@` query filters the whole list again, since only a query that extends the last one narrows: 2.4 ms over 100,000 paths. Step 21's review found both; neither is in the editor demo's measurement. Recommendation: lay out only from the row the change is on, cached by the text's version, and keep the matches of each shorter query while the menu is open. | Step 33 (performance pass) | Before the first release |
