| **The editor's cost on very large text is not measured against the key budget.** Every key lays the whole prompt out again (grapheme segmentation of all of it) and finds a chip's label by counting the chip marks before it, so after `Ctrl+X` expands a paste of several megabytes into the prompt each key costs time in proportion to it. And `Backspace` or `Left` inside an `@` query filters the whole list again, since only a query that extends the last one narrows: 2.4 ms over 100,000 paths. Step 21's review found both; neither is in the editor demo's measurement. Step 23's review found a second way into the first without `Ctrl+X`: a prompt that comes back into the editor (refused, or steering an interrupt hands back) comes back as its whole text, a paste's chip expanded, because the application keeps the text it sent (`Pending::Prompt`, `TurnInterruptResult::undelivered`) and not the editor's fragment; what the editor held beside it keeps its chips since the fixes after that review. Recommendation: lay out only from the row the change is on, cached by the text's version, and keep the matches of each shorter query while the menu is open; keep the fragment a prompt was sent from, and give that back. | Step 33 (performance pass) | Before the first release |
