| **Two names that are one name as the model is shown them.** Since the fixes of the independent review of step 18, a name is shown with every character that would act unseen escaped ([05-tools.md](../architecture/05-tools.md), "Names and lines from the workspace"). Two names can then be one text: a file named with a zero-width non-joiner and another, on Linux, named with that escape spelled out (`a\u{200c}b`). `list` keeps its entries by their shown text, so it counts both and shows one, and its "more not shown" note says one more than it hides; `search` keeps a file's matches by its shown path, so the second file's matches take the first's place while both are counted; and the path resolver, given the shown text, takes the file that is spelled that way first. Only a workspace that names files to collide this way meets it. **On the terminal, two names can look alike without being one text** (since step 23): `cortex-term`'s `sanitize` keeps the zero-width joiner and non-joiner in what it draws, by the owner's choice of 2026-11-15, since they join emoji sequences and shape Persian and the Indic scripts, so two names that differ only by one of them are drawn the same, in a menu, a picker or a tool's line. **What a fix would take:** key `list`'s entries and `search`'s files by the path as data and show the escaped one; the resolver's choice stays, since the text the model gave names one of them as written. | A later `cortex-tools` step, or step 32 | When such a workspace is reported, or before the first release |
