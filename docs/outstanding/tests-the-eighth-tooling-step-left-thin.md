| **What the eighth tooling step's tools do that no test holds, and their small faults** (its reviews). None lets a check pass when a test failed. `cargo xtask ci`'s wiring of the re-run after a stall (`ci_test_steps` passing `rerun`, the records the runs write, the tiers each run is given) is glue no test reaches, as are the re-run's paths that put the first report back when the re-run left none or its report could not be written; a break of any of them fails safe (no re-run, or the tiers judged). `apply`'s `@@ check: fmt` runs `rustfmt` on the files the script touched, which also formats their out-of-line modules: those are not in the plan, so a later failed check does not put them back (harmless while the tree is formatted). **`mutate`:** the `caught-by` names of an `os:` break, looked for among the source's words, prove nothing for a test whose name both systems' modules have (`tooling-7/nofollow-windows-follows-a-reparse-point` names one such: renaming the Windows test still passes); requiring the module's segment as a word of the same file would; and the jobs test's window is a few milliseconds of clock, so whether a missing lock is caught depends on a thread being scheduled within it (a hook before the claim would make it exact). **`perf-ab`:** a measurement missing from some rounds of one side shows its median over fewer values with nothing said, and a run in which no test printed a `perf:` line exits 0. **`size --at`** builds the commit inside the workspace's `target/`, so the working tree's `.cargo/config.toml` applies to the old commit's build (it holds only an alias today). **The console's close on Windows:** its two tests read only that the request was dropped or the command is gone within 2 s, which the console host's own end of every process on the console also gives, so an application that ignored `CTRL_CLOSE_EVENT` would pass there; a mark of the application's orderly end (its exit code, or a line its handler leaves) would hold it.
