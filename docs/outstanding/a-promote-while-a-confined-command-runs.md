A promote made from another process while a confined command of the same project runs is taken for a change from outside, and stops that command's turn.

- Area: cortex-knowledge
- Owner: a fix session that changes the continuity check

| Item | Who | When |
|---|---|---|
| **A `promote` made from another process while a confined command runs can stop that command's turn.** `project/update`'s `promote` writes the repository's shared profile, `.cortex/profile.toml`, which is a protected path: the sandbox looks at the protected paths before and after every confined command, and a change it finds that the command did not make stops the turn as a change made from outside ([06-permissions-and-sandbox.md](../architecture/06-permissions-and-sandbox.md)). **Since step 24 the core refuses a promote with `turn_running` while any session of the project in that core runs a turn,** so neither the project panel, another client of the core, nor a turn started between the panel's look and its key can write the file under a confined command ([steps/24/answered.md](../steps/24/answered.md)). **What is left:** `cortex project promote`, or a second core, in another process at the moment a confined command of a session of the same project runs: the turn stops with a notice that names the file, and nothing is lost. **Recommended:** the checkpoints take a pending write (set before, cleared after the write or its refusal) that a command's own look passes over for that one path, which needs the promote to reach the running core rather than write the file itself. | A fix session that changes the continuity check | Before promote is offered where two processes commonly share a project |
