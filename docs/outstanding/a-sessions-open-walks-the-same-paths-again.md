The number of walks was left: an open walks 29 paths, and each still ends in a `canonicalize` (26 to 51 µs a call on a hosted Windows runner). Among them: each load of the configuration makes its own project locator, which walks the workspace, then walks it again for each project file, and `LiveConfig::start` does that twice (the files' stamps, then the read): six walks for two files; the home folder is resolved by `place` for the trust look and again for the assembly, and by `engine_parts`; and `engine_parts` resolves twelve folders with `resolve_dir`, several under the same home. **What it would change:** today each walk looks at every name of the path from the drive's root, so a link swapped into an ancestor of the workspace between two looks in one open is seen at the second; reusing a walk would see it only at the next open, and widens the moment the residual in [security.md](../security.md), section 7, describes.
