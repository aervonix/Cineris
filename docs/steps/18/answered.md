# Answered in step 18, on 2026-11-15

Step 18 built the repository map: `cortex-index` (fifteen languages' extractors and an indentation fallback, the on-disk cache, passes under caps, ranking and the map), the map in a context epoch (`cortex-agent`), the `outline` tool (`cortex-tools`), and a session's index (`cortex-core`). ## The six points

The coordinator approved all six as proposed on 2026-11-15.

| Point | Settled | Recorded in |
|---|---|---|
| **1. The fifteen languages.** | Python, JavaScript, TypeScript, Java, C#, C, C++, Go, Rust, PHP, Ruby, Kotlin, Swift, shell and Markdown: the languages with the most activity on public code hosts, and Markdown because nearly every repository documents itself in it. Four engines over one lexer: braces (with nesting by what a body holds: types, `impl` blocks, interfaces and modules hold definitions, a function's body nothing), indentation (Python, Ruby), Markdown's headings, and the indentation fallback for every other text file (a line with more indented lines under it is a block, two levels deep). The first line of a doc comment right above a definition is its summary. Each extractor is text in, outline out. | [architecture/15-efficiency.md](../../architecture/15-efficiency.md), "Repository map" |
| **2. The cache.** | One file a project, `<state>/projects/<project key>/index/outlines`, text, owner-only by an atomic replace, unflushed. Keyed by path, size, modification time in nanoseconds and, on Unix, the inode and its change time. A file modified within two seconds of the pass that read it, or after it (a clock set back), is unsettled and read again by every pass until it settles. Bounded by the caps; another version, another root, a cut or a count that does not add up is no cache, rebuilt by the next pass. Two writers: the last replace wins, both valid. | The same; `cortex_index::cache` |
| **3. Ranking and rendering.** | A budget of 1,500 tokens at three bytes a token: a fixed lead, the counts (and "partial", with why, when a cap bit or a pass was cut short), the tree in at most 30% (whole levels of directories with their file counts), then the files, each whole or not at all, with a line saying how many were left out. Ranked by the files this session touched, the files of recent sessions (a seam), the files changed most recently when the tree's times say anything, then definitions, depth and path. Byte-stable: total orders ending at the path, the touched files a set, no times and no absolute paths. | The same |
| **4. When the map changes.** | One map an epoch. A compaction's epoch gets a fresh one; a change of model and a resume keep the map their history holds, never built again or compared, so a resume that would find a different map stays in its epoch at no cost to the cache. An epoch whose history holds none gets one at its next chance. The prompt cache pays one map's tokens of writing in each epoch, and nothing else. | The same; [architecture/07-sessions-and-context.md](../../architecture/07-sessions-and-context.md), the seams map |
| **5. Background indexing.** | The blocking pool. The core makes a session's index touching no file; the first pass starts once the loop runs. A pass gives way to a running turn when nobody waits for a map, carries on when the turn ends (the idle slices), and stops at its next file when the session ends. A pass cut short while listing writes nothing; one stopped while reading writes what it has. | 15-efficiency, "As built in step 18" |
| **6. The `outline` tool.** | The ordinary output limit, shaped by the tool; a directory's files in path order, each file's outline to its first 30 definitions; workspace only (a path outside is refused when planned); a file over 1 MiB is outlined from its first 1 MiB, one in no language from its indentation, each said; a binary file has none. **A large file's `read` does start with its outline:** step 6 built that behind `Outliner`, and the core now fills it. | [architecture/05-tools.md](../../architecture/05-tools.md), "`outline`" and "`read`" |

## Choices made on the way

| Choice | Why | Recorded in |
|---|---|---|
| **A pass holds one window of 512 listed files' outlines at a time**, writing each window's records out before the next is read, and the cache's summary line comes after its records. | The first version held every outline of a cold pass until the cache was written: a cold pass of 20,000 files peaked at 33.5 MB resident and left 24 MB with the allocator. With windows: 13.1 MB at the peak and 7.1 MB after, which later passes reuse. | [performance-budgets.md](../../performance-budgets.md), "Memory"; `cortex_index::pass` |
| **The memory check is the process's resident memory, on Linux,** not a count of the heap. | Counting the heap byte for byte needs an allocator of the test's own, which is `unsafe` code, and the workspace allows that in three named modules only. Twenty more passes and maps must not grow the resident memory after a warm-up. | `cortex-index`'s `memory::passes_and_maps_leave_nothing_behind` |
| **`[index]` is declared:** `map`, `map_tokens`, `map_wait`, `max_files`, `max_file_bytes`, `pass_time`. The budget and the caps are tighten-only; the caps take effect at a restart. | The section was reserved for this step. The map's budget was planned under `[adapt]`; it sits with the map. | [architecture/08-configuration.md](../../architecture/08-configuration.md); [configuration/reference.md](../../configuration/reference.md) |
| **The core's test rig has no index unless a test asks** (`CoreOptions::repo_index`). | A late map arrives at a boundary of its own timing, which tests of exact requests do not want. The real binary's system tests run with the index on. | `crates/cortex-core/tests/it/main.rs` |
| **A directory's outline gives each file at most 30 definitions.** | One large file in path order would otherwise take the whole result and leave the directory's other files out. | 05, "`outline`" |
| **The toolbox the binary sends now has `outline`**, and its recorded fixtures do not. | A recording is a paid call: [outstanding](../../outstanding/the-toolbox-fixtures-without-outline.md). The system test that compares them warns and does not fail. | — |
