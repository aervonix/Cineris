# Step 28, its parts: managing extensions

The second part of step 28's third pull request ([answered.md](../answered.md), "The design, before building", point 10, item 3): managing extensions (`cineris ext list|inspect|add|disable|remove`, `extensions/status`); the guards that keep a session's commands from approving an extension or trusting a project for the model; the RPC server's refusal of its own commands, shown for hooks and extensions' programs; and the first run's question on reading skill folders ([12-extensions.md](../../../architecture/12-extensions.md), "As built in step 28: managing extensions"; [06-permissions-and-sandbox.md](../../../architecture/06-permissions-and-sandbox.md), "The harness's own approving commands").

## What was built
