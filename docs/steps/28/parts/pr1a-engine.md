# Step 28, its parts: the engine

The first of step 28's pull requests: `cineris-ext`'s folder snapshot, manifest, capabilities, engine and host-function contract, and the core's host for them, with an extension's tool called end to end ([answered.md](../answered.md), "The design, before building", and its cut).

## The early review of the host functions' permission path

A reviewer that had not seen the author's reasoning read the capability and permission path at its first complete state (`cineris-ext`'s `host`, `capability` and `engine`; the core's `ext` module and its use of the policy) against the bar the maintainers set: any way to act without the manifest and the policy, anything running before approval, a limit that does not hold, a test that passes with its feature removed, a path check fooled by a path that is not canonical. Each finding was fixed with a test and a break in [mutations/step-28.breaks](../../../../mutations/step-28.breaks).

| Finding | Fix |
|---|---|
| **A script could end the whole process,** before approval as well as in a session. A getter on a definition, `toJSON` in a schema, or `Error.prepareStackTrace` (which the engine runs as it makes an error) called back into the engine while `register` or a host call held the thread's state: the thread panicked, the unwind skipped freeing what the runtime kept, and the engine's own check as the runtime was freed ended the process. | A definition is read whole before anything is held, and every error is made after it is let go; a call that comes back in is refused, not a panic. A guard frees what the thread keeps on any end of it, an unwind included. The prelude makes `Error.prepareStackTrace` impossible to set. |
| **"Allow once" on a host call was reused** for a later host call of the same tool call that asked the same question: every host call is planned under its tool call's item, and the answer was remembered by it. A second write to a file under an `ask` rule ran unasked, its diff never shown. | What a host call was allowed is never remembered. |
| **Nothing bounded what a script's calls took into the harness:** arguments of any size were parsed and queued while one call waited, outside the runtime's memory limit, and the specification's counts were not kept. | Each kind's arguments are bounded by size before they are taken; at most sixteen calls a script awaits wait at once; in one call, ten notices, a hundred progress lines, a hundred lines of the log and five questions, each of at most eight choices, its answer one of them or none. What a script shows passes through `visible`. |
| **The session's capabilities came from the approved manifest,** a field apart from the hash the runtime checked. | The runtime's manifest, from the snapshot whose hash was checked, must equal the approved one. |
| **The manifest and the engine could judge different paths:** a write and a walk were planned again from the script's text, and a read opened its path by name after a decision that may wait on a person. | A write or a walk whose plan touches another path than the one the manifest judged is refused; a read opens its file only if its path still leads where it was judged to. Opening by name after the decision is a residual the built-in `read` and `write` tools share; it was raised with the maintainers. |
| **The file system was probed before the manifest refused,** and a refusal showed where a path led, and a resolver's error was passed on. | A refusal names the path as the script gave it and is the same however the path failed; a manifest that grants no reading or writing refuses before the path is resolved. |
| **A program was given the call's whole time,** not what was left of it, and the test of it called `serve` directly. | What is left, from the session's clock; an engine-level test moves the clock on before the program is asked for. |
| **Two parts of the wiring had no test:** the manifest's gate on a script's walk, and the `ext` effect on each host call. | A listing shows only what the manifest reads; a rule about the extension makes a script's plain read ask. |
| **Lower points:** a stop flattened to a refusal, so the script went on; an answer not among the choices taken; a file with a NUL byte read as text; a read recorded as showing the whole file; a deeply nested result made many times larger by indentation. | A stop ends the script's call, and wakes a thread waiting for an answer, which the interrupt never reaches (this also ends the 2 s grace a deadline during a host call used to cost). It also stops the turn, as a confined command that changed protected paths does, so no call after it runs and the turn ends `denied`: a second reviewer, asked for a fix narrower than a change to the loop, found it. What only the loop can close, a stopped call that is the last of its response, is open for the owner: [a-stopped-host-call-does-not-end-the-turn](../../../outstanding/a-stopped-host-call-does-not-end-the-turn.md). The others as the finding says. The phase is not added to the `Host` trait: the core's host is made for each call and will carry it in the step's hooks. |

**What it checked and found sound:** the manifest asked before the host for every kind of call; host calls refused during the first evaluation; globs that refuse `..`, a root, `~` and a drive, and grant nothing outside the workspace; paths resolved for `~`, relative paths, `..`, links both ways and case on Windows; a walk that gates every entry and follows no link; host questions offering only "allow once" and "deny" and keeping nothing; the snapshot read whole, links refused, imports only from it; no check living only in the prelude; values crossing as JSON text only; `RunCx::call` set only by the round and read only by the extensions' host; interrupts a script cannot catch; an extension's tool always `Ask` and `Exclusive`.

## The early review of the extensions' process starts

A second reviewer, who had not seen the author's reasoning, read `cineris.exec` (the program's lookup, the line the engine reads, the start through the launcher or `cmd.exe`, the launcher's input, the look at protected paths) against the same bar, and looked for the same mechanisms in the harness's other starts.

| Finding | Fix |
|---|---|
| **High: a write root that was a link granted writing wherever it led.** The roots were resolved just before the launcher saw them, so its open that refuses a link passed: `build -> ~`, made unasked by a confined command or shipped by a cloned repository, granted the home folder. | The roots reach the launcher as the workspace's real path joined with their names, never resolved, so a link on the way is refused; roots that hold the harness's own files run no program. |
| **A batch script that takes its argument's quotes off** (`set T=%~1`, then `%T%`) made `& | < > ^ ( )` live. | Those characters are refused in an argument to a `.cmd` or `.bat`, named, as `"`, `%` and `!` were; an npm shim's `--x=(a)` is refused too, an accepted cost (settled by the maintainers). |
| **A folder a reload made writable was not passed over** by the search for a program, nor by the harness's git: both kept the roots the session started with. | Both avoid the roots the sandbox holds now. The open item on the harness's git, from the harness's own processes' fixes, is settled. |
| **A `.exe` reads its own arguments:** an MSYS program globs an unquoted `*` and takes `'` as a quote; an ANSI program's best-fit turns `＂` and `＼` into `"` and `\`. | Every argument of a `.exe` is quoted with the C runtime's escaping, and the four lookalikes are refused (settled by the maintainers). |
| **In PowerShell and `cmd` the engine reads a program's line by that shell's own commands and aliases** (`write` is `Write-Output`). | Where the session's shell is not POSIX, a program the engine allows as read-only is asked about; the engine-side fix is an open item for the hardening pass ([an-extensions-program-is-judged-by-the-sessions-shell](../../../outstanding/an-extensions-program-is-judged-by-the-sessions-shell.md)). |
| **A program's own lookups kept the workspace's folders** on its `PATH` (a wrapper's `env node`). | Its `PATH` leaves out the folders no program is taken from. |
| **Two pages said programs ran under the narrower of the session's policy and the manifest,** with no word on Windows. | Both say what the launcher gives at every level, and that on Windows nothing binds them. |
| **The input's seal test** wrote only after reading to the end, where the seal against growing refused alone. | It writes at the start first; a break of the seal against writing alone is caught. |

Two of the maintainers' calls came with it: a program's writes are recorded in the round's checkpoint, so undo puts them back, through the shell's own change detector; and a question about a program says whether the extension's own launcher confines it, which at `unrestricted` the session's level did not. The reviewer's grep of the other starts found the shell tool's `cmd.exe` line, `Shell::quote`, the shell's and git's searches and the external editor sound for what they carry; one robustness gap is open for the hardening pass ([a-windows-program-lookup-takes-a-file-with-no-extension](../../../outstanding/a-windows-program-lookup-takes-a-file-with-no-extension.md)).
