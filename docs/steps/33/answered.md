### What this fix decided within those answers

- **`release` is at "s" too**, and `dist` inherits it. The perf tools (`cargo xtask perf`, the `perf_` tests, `try -f profile=release` and `perf -p`) build in `release`, and start-up is measured on `dist`: with `release` at 3, every speed figure of record would have described code that does not ship. Building the perf tools in `dist` instead would have made every measurement wait for fat LTO over one unit. Nothing builds at `opt-level = 3` now.
- **The pin is a requirement, not only a lockfile entry.** `url` asks for `idna_adapter = "1"`, so `cargo update` would undo a lockfile pin without a word. `cortex-llm` names `idna_adapter = "~1.0.0"` (optional, under its `http` feature), only to hold it, with the reason in the root `Cargo.toml` and in [dependencies.md](../../dependencies.md); a test of its transport fails if the lockfile's adapter is not 1.0.
- **A host with letters outside ASCII is refused by the harness, not only by the URL library,** whose error says nothing useful: the core refuses a provider's `base_url` with one (`invalid_provider`, naming the key and the `xn--` form), and the transport refuses any such request before a client exists. A provider's base URL is the one place such a URL can reach the binary today.
- **The remapping is in `xtask`, not in the manifest.** Cargo's `trim-paths` is not stable on 1.99.1 (it asks for the nightly feature), and a profile's `rustflags` is not stable either. So every build of the shipped binary through `xtask` (`size`, `startup --profile dist`, and step 34's `dist`) sets `CARGO_ENCODED_RUSTFLAGS` to the flags already set and one `--remap-path-prefix` for each of the home folder, cargo's home, the sysroot, the workspace and the target directory, from the most general to the most specific (rustc applies the last that matches). A plain `cargo build --profile dist` is not remapped; the check finds that.
- **The check reads the binary as bytes** for the shape of a home path, with the repo rule's finder (`/home/<name>`, `/Users/<name>`, a drive letter and `\Users\<name>`), and for the build's own `CARGO_HOME` in either separator and any case. In a binary, strings are packed end to end, so there a root counts after a letter too. It prints each kind with the user's name left out. `size` fails on it whether or not `--check` is given. `cargo xtask home-paths FILE…` reads any file.
- **The pull-request job is `pr-size` in `ci.yml`,** after `needs: [lint, test]`. It skips a pull request whose every file is documentation, a list of breaks, `xtask/**` (but for the five files the shipped build and its verdict go through: `shipped.rs`, `nonblocking.rs`, `steps.rs`, `workspace.rs`, `rules/home_paths.rs`) or a workflow.
- **The decision record was written by hand.** The brief asked for it through `cargo xtask decide`, which is the permission engine's probe and does not write records.

### Shown on a desk build

A plain `cargo build --profile dist` at the desk (at `61bd1a0`), then `cargo xtask home-paths target/dist/cortex`: it failed, with `/home/<user>` 512 times (the first followed by `/.cargo/registry/src/index.crates.io-…/h2-0.4`) and the build's `CARGO_HOME` 529 times. The same tree through `cargo xtask size`: `paths none under a home folder or cargo's home`, and 7,960 bytes smaller.

### Breaks

`mutations/step-33-size-fix.breaks`, run with `cargo xtask mutate step-33-size-fix --jobs 2` at the desk: **18 breaks, each caught by the test it names, none flagged.** They break the binary check (it is skipped; a path packed against the string before it is passed over; the cargo home in one spelling or one case; the user's name shown; a name outside ASCII; the build's own home not looked for; a longer folder taken for it), the remapping (no folder remapped; the flags already set dropped; the home folder after cargo's), `size`'s ending (a home path passing a run without `--check`; over the budget passing; the difference from `main` losing its sign), and the refusal of a host outside ASCII (not found; the port taken for the host; the transport handing it to the URL library; the core taking a provider's). The first run found one break no test caught (the build's own home folder, which only `check_file` looked up): a test of `own_folders` was added. Not broken: the pin itself, which a break could move only with a new lockfile, and the paths the `changes` action counts, which are shell outside any crate's tests (checked by hand against ten sets of paths).

### The independent review

A fresh reviewer, which had not seen this work's reasoning, read the whole diff against the brief before the first push. It found nothing that must be fixed: the branch's `main` run had shown the remapping and the check working on both runners. What it found, and what became of each:

| Finding | What was done |
|---|---|
| **The size job skipped a change to the `xtask` files the shipped build goes through.** Only `shipped.rs` counted; a pull request that broke `steps.rs`'s environment or `workspace.rs`'s folders would have lost the remapping and shown it only after the merge. | **Fixed.** `nonblocking.rs`, `steps.rs`, `workspace.rs` and `rules/home_paths.rs` count too (the `changes` action, `testing-and-ci.md`); the classification was run against ten sets of paths. |
| **The binary check missed two real cases:** a user's name starting with a letter outside ASCII (`/home/émile`), and a home folder of no common shape (`/root`, a container's). | **Fixed,** with a test and three breaks: in a binary a name's bytes may be 0x80 and above, and the build's own home folder is looked for by name, as a whole folder, as its cargo home is. |
| **`CARGO_ENCODED_RUSTFLAGS` takes the place of every `rustflags` in cargo's configuration,** not only `RUSTFLAGS`. | **Said** in `encoded_rustflags`' documentation: the repository sets none. |
| **`ci-wait --pr` and `ci-times` count `pr-size` with the blocking jobs;** the difference is from `main`'s newest record, not the base; a change to the job is not run on its own pull request. | **Outstanding:** [the-pr-size-jobs-rough-edges](../../outstanding/the-pr-size-jobs-rough-edges.md). |

It traced every break to the test that catches it.
