## As built

- **`api-diff --features CRATE/FEATURE,…`** turns features on when documenting both trees, so a test kit behind one shows: `api-diff -p cortex-tui --features test-kit`, `--features cortex-tui/test-kit,cortex-policy/test-support`.
  A bare feature name needs exactly one `-p`; a feature of a crate not compared, or one the working tree's crate does not have, is refused before anything is built; one the ref's crate does not have yet is left off there and said.
  **What trying it found:** `cargo doc -p cortex-tui --features cortex-tui/test-kit` turns nothing on (the rustdoc call's `--cfg` had `default` and `highlight` alone), where `--features test-kit` does. The review found why: `cortex-tui` and `cortex-policy` each have a dev-dependency on themselves that asks for the feature, for their tests, and cargo takes `CRATE/FEATURE` as that dev-dependency's (`cargo tree -e features`), while a crate without one (`cortex-sandbox`) takes it as its own. So each crate asked for features is documented in a call of its own with the bare names, and the rest together in one call, as before.
  **Run at the desk** (`rx --git`), against `91e6e20e~1`, the commit before the kit: `cortex-tui: 34 added, 0 removed, 0 changed`, every one of them `cortex_tui::testkit::…`, with `the base tree has no feature cortex-tui/test-kit: documented without it there`. Without the fix of the calls it said `no public API changes`, which is how the problem was found.
  Tests: `api_diff::tests::features_are_read_with_their_crate`, `a_feature_is_turned_on_where_its_crate_has_it_and_said_where_it_does_not`, `each_call_of_cargo_doc_has_its_crates_and_its_features_and_no_other` (the arguments each call gives cargo), `a_feature_of_a_crate_not_compared_or_that_the_crate_lacks_is_refused`. The ignored test against the real rustdoc, which the nightly runs, has no feature case. Breaks: `api-diff-*` in `mutations/tooling-10.breaks`; `tooling-7/api-documents-with-the-stable-compiler-alone` follows its code into `document_once`.
