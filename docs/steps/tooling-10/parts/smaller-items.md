# The tenth tooling step: the smaller items

Item 5, and what was done of item 6. One sentence a line.

## As built

- **`api-diff --features CRATE/FEATURE,…`** turns features on when documenting both trees, so a test kit behind one shows: `api-diff -p cortex-tui --features test-kit`, `--features cortex-tui/test-kit,cortex-policy/test-support`.
  A bare feature name needs exactly one `-p`; a feature of a crate not compared, or one the working tree's crate does not have, is refused before anything is built; one the ref's crate does not have yet is left off there and said.
  **What trying it found:** `cargo doc -p cortex-tui --features cortex-tui/test-kit` turns nothing on (the rustdoc call's `--cfg` had `default` and `highlight` alone), where `--features test-kit` does. So each crate asked for features is documented in a call of its own with the bare names, and the rest together in one call, as before.
  **Run at the desk** (`rx --git`), against `91e6e20e~1`, the commit before the kit: `cortex-tui: 34 added, 0 removed, 0 changed`, every one of them `cortex_tui::testkit::…`, with `the base tree has no feature cortex-tui/test-kit: documented without it there`. Without the fix of the calls it said `no public API changes`, which is how the problem was found.
  Tests: `api_diff::tests::features_are_read_with_their_crate`, `a_feature_is_turned_on_where_its_crate_has_it_and_said_where_it_does_not`. Breaks: `api-diff-*` in `mutations/tooling-10.breaks`; `tooling-7/api-documents-with-the-stable-compiler-alone` follows its code into `document_once`.
- **The sandbox's socket test binds its listener in a short folder of its own** (`/tmp/cxs-<test>-<process>`, removed when the test ends), not in its scratch folder under `TMPDIR`: a Unix socket's path has room for about 108 bytes, and a scratch folder under a long `TMPDIR` (the copy the desk's `rx` builds in) has more, so the bind failed whatever the test was about. Its twins were looked for: `cortex-base`'s two tests that bind a socket already use a short folder (`Scratch::short`), and no other test binds one. Passes at the desk under `rx` with no `TMPDIR` of its own (`confined::sys_with_the_network_off_no_socket_reaches_anything`).
- **`mutate --check --tests` runs every night,** in the nightly workflow's new `break-names` job, so a `caught-by` that names a test that was renamed or removed is found within a day, and its failure opens the nightly's issue. Not in the blocking jobs: it builds the tests of every set of crates the breaks run (42 sets), minutes of a build.
  **`caught-by-names-checked-only-at-the-desk` is settled** and its file deleted: the names are now checked in CI, every night. What is left is the owner's: a blocking job could run the check after its own build, at minutes more; this step did not add it (rule 2).
