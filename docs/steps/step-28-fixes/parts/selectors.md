# The fixes to step 28, variation selectors

Finding 6 of the review of step 28, alone in the first pull request, since step 30's MCP client gives its servers' descriptions to the model through `cineris_base::one_line`.

## Finding 6: variation selectors reached sections 6 and 7

- **What it was.** `cineris_base::one_line` (a skill's name and description, a tool source's description: section 6) and its twin `plain` in `cineris-agent`'s `context/prompt.rs` (section 6's skills part and every section 7 text) kept a variation selector after any character kept, and went on keeping them: the flag that said "a selector may follow" was not put down after one. A run of selectors carries any bytes unseen, one a byte, so a repository's `SKILL.md`, which needs no trust, could hide an instruction in its description that no reader of the file sees and no interface shows.
- **Why not one selector a character.** The review's fix, one selector after each character kept (as `visible_keeping_after` shows text to the person), leaves a byte a character: the pre-push review put one after each letter of "Fill in PDF forms.", a line that reads as it did and carries 18 bytes, about 60 in a skill's 300-byte description and 800 in a 4 KiB text; a combining mark or U+2800 repeated, each with its selector, makes a carrier that reads as nearly nothing.
- **The fix.** Both take out every variation selector. The text is for the model, to which a selector (how the character before it is drawn) means nothing, an emoji's included. Text shown to the person (`visible`, the terminal's `sanitize`) still keeps one after a character shown as it is; a skill's name and description, already made one line when they are read, are shown to the person without them too.
- **A skill's path.** Section 6 names each skill's file by a path written with `visible`, which kept a selector after a character as it is: the prompt's `plain` would now take it out and name a file that is not there (the second round of the pre-push review). The path is written with `cineris_base::visible_to_the_model`, new, which writes every selector as its escape, and the escape reads back as the path (`unescape`, which the tools try after the path as it is).
- **The twins.** Every other reader of selectors (`visible_keeping_after` and so `visible` and the terminal's `sanitize`, `unescape`, and the test kits' checks) keeps one a character at most, for the person's eyes. Two of them judge text that reaches the model: a project command's body and its arguments' defaults (`cineris_ext::commands`), and what a script registers (`cineris_ext::registration`); both refuse what acts unseen and pass one selector a character. They are settled in the third pull request.
- **Tests,** each failing without the fix (the review's runs at `5eda6204` showed the run), and the path's without its own:
  - `cineris-base`: `visible::tests::one_line_keeps_no_variation_selector`: a run after a character, a selector after each character of a line, after combining marks, a Mongolian one and an emoji's, all taken out; 2,000 seeded texts of letters, spaces, line breaks, joiners, combining marks and selectors of all three ranges leave none.
  - `cineris-ext`: `skills::tests::no_variation_selector_of_a_skill_reaches_the_index`: a project's `SKILL.md` with a payload in its name and one byte after each character of its description renders none; `skills::tests::a_skills_path_holds_its_selector_as_an_escape`: a folder named with an emoji and its selector is listed and rendered with the selector as its escape, which reads back as the path.
  - `cineris-base`: `visible::tests::a_name_for_the_model_has_every_selector_as_an_escape_and_reads_back`.
  - `cineris-agent`: `context::prompt::tests::no_variation_selector_reaches_the_index_or_a_text` (section 6's skills part and a section 7 text), and `extensions::no_variation_selector_reaches_the_prompt` in the integration binary (a real request's system prompt).
- **Breaks** (`mutations/step-28-fixes.breaks`): `one-line-keeps-selectors` and `plain-keeps-selectors`, each the fix's test of a selector taken out, and `a-skills-path-keeps-its-selector`, the path written with `visible` again.
- **What it changes for a session.** A section 7 text that held a selector is now written without it, so its part has a new hash, once: a resume over a log whose epoch held such a text begins a new epoch, as any change to a text does (07, "Section 7 is inside `base`"); an index that held one has a new hash once, and a resume over it is told the index whole.
- **Docs.** 07's section 7, 12-extensions' skills and security.md §3's skills row say that no selector is kept; each was untrue of the code before.
